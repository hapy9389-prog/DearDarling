# DearDarling 요구사항 및 설계 v0.2

최초 작성일: 2026-09-09 · 갱신일: 2026-09-11
용도: 사내/지인 테스트 웹 서비스
상태: 가상 데이터 화면 구현·검토 이후, 로컬 API·PostgreSQL 기반 구현 중

v0.1의 제품 원칙과 13개 장 구성을 유지하고, 이후 합의·구현으로 달라진 부분만 갱신했다. 원본 v0.1은 변경하지 않는다. 이 문서의 ‘구현’은 화면/로컬 코드/실제 서비스 연결을 구분하며, 배포나 보안 검증 완료를 뜻하지 않는다.

주요 변경:
- 3탭 제안 → 홈·대화·우리·추억 4탭 및 별도 설정, 우리 탭에서 개인 AI 상담 진입.
- 양측 ‘맞아요’ 확인 모델 → 관찰·개별 의견·코칭 활용 중단을 분리하는 모델.
- 추억 화면과 저장 흐름, 온보딩, 표현 도움 등 현재 구현 상태 반영.
- Amplify·Fargate·ALB·RDS 제안 → 비용을 낮춘 EC2 단일 서버·PostgreSQL·Cognito 기준안.
- 지금 할 로컬 구현과 이후 실제 인증·화면 연결·AWS 배포를 분리.
- 회사 AWS·서울 리전·키 수령은 전달받은 사실로 기록하고, 실제 권한·비용·배포 완료로 해석하지 않음.

## 1. 결정의 기준

사용자가 직접 작성한 서비스 정의와 이후 합의한 변경을 제품 기준으로 삼는다. 회사 기획안과 HTML은 참고 자료이며, 모든 제안을 구현 요구사항으로 취급하지 않는다. ‘웹 우선, 이후 앱 확장, 회사 AWS 배포, PostgreSQL, 회원가입’을 우선한다.

확정된 방향:
- 연결된 두 사람의 실제 대화에서 필요한 순간 AI가 소통을 돕는다.
- 주간 관찰 → 사용자의 선택적 의견·코칭 제외 → 이후 코칭에 반영하는 순환을 만든다. 두 사람이 확인 버튼을 눌러야만 활용하는 방식은 사용하지 않는다.
- AI가 답장을 자동 전송하거나 상대의 감정을 사실처럼 단정하지 않는다.
- 커플 대화 분석은 양측의 명시적 동의를 전제로 한다. 동의 기본값은 꺼짐이며 가입·연결·일반 대화의 필수 조건이 아니다.
- Codex는 설계·검토, Claude Code는 합의한 단위의 구현을 맡는다. 같은 파일을 동시에 수정하지 않는다.

화면 규칙은 현재 의사결정 기록 0002~0010을 반영했고, 로컬 API 범위는 작성 중인 0011도 참고했다. 인프라 내용은 최신 합의된 배포 기준안이며 실제 구축 완료가 아니다. 테스트 규모·성능·비용 상한·데이터 보존 기간 등 명시적으로 미정인 항목은 여전히 제안이다. 과거 문서와 충돌하면 이후 명시적으로 합의된 결정이 우선하며 관련 문서에 대체 관계를 남긴다.

## 2. 첫 테스트의 범위

초기 계획 가정: 성인 참여자 5~10쌍, 2주 테스트, 한국어 텍스트 대화, 모바일 브라우저 중심. 규모와 예산은 실제 참여자 모집·배포 전에 확인한다.

실제 서비스 연결 목표:
1. 이메일 가입·인증, 로그인·로그아웃·비밀번호 재설정.
2. 제한된 테스트 참여, 커플 초대·연결, 연결 상태 확인.
3. 텍스트 메시지 전송·수신·저장·재접속 복구.
4. 양측 AI 분석 동의·철회, 개인 코칭 표시 설정.
5. 맥락 코칭 카드, 근거 확인, 추천 답장 선택·수정·수동 전송.
6. 선택적으로 켜는 작성 중 표현 도움.
7. 주간 관찰 리포트, 각자의 의견, 관찰별 코칭 제외·본인 선택 해제.
8. 대화에서 직접 추억 저장, 공동 앨범, 메모 수정·삭제. AI 발견 제안과 개인 상담의 실제 연결은 후속 AI 작업으로 구분한다.
9. 연결 해제·탈퇴·데이터 삭제 정책과 구현, 오류·비용 관측.
10. AWS HTTPS 배포와 DB 연결, 실제 두 계정의 종단 간 검증.

현재 상태:
- 홈·대화·우리·추억·설정, 개인 상담 진입점, 가입·로그인·연인 연결은 가상 데이터로 화면 구현·검토를 진행했다. 일부 저장은 브라우저 localStorage이며 서버 DB 저장이 아니다.
- 신규 체험 계정과 민준·서연 예시 검토 모드는 분리된다. 신규 체험에 실제 AI 분석이 수행된 것처럼 시드 결과를 제공하지 않는다.
- 로컬 API·PostgreSQL 기반 코드가 작성 중이다. 2026-09-11 폴더 확인 시 미커밋 파일이 존재하나, 이번 문서 갱신에서 실행·테스트 완료를 확인한 것은 아니다.
- 실제 Cognito 인증, 웹의 실제 API 연결, 기기 간 대화 수신, AI 분석, AWS 배포는 완료로 보지 않는다.

후순위: 실제 사진/영상 업로드·분석, AI 이미지 생성, 통화, 기념일 앨범 확장, 관계 점수, 결제, 소셜 로그인, 네이티브 앱, 웹 푸시. 추억 탭 자체와 개인 상담 진입 화면은 이미 있으므로 ‘화면 미구현’으로 분류하지 않는다.

백그라운드 알림을 제외한 웹 테스트는 ‘메신저 완전 대체 가능성’까지 입증하지 않는다. 상대 동의 없는 실제 대화 업로드·분석은 이번 범위에 넣지 않는다. 검토 모드의 예시 체험을 실제 1인 분석 서비스로 설명하지 않는다.

## 3. 화면과 주요 상태

하단 탐색은 **홈 / 대화 / 우리 / 추억** 4개다. 설정은 홈 상단에서, 개인 AI 상담은 우리 탭의 작은 버튼에서 진입한다. 로그인 전에는 시작·가입 흐름을 제공하며, 로그인 후에는 세션·프로필·연결 상태에 맞게 이동한다. 온보딩과 `/app/*` URL 이동은 react-router 기반이고, 앱 안에서 탭을 오갈 때 대화 화면의 상태를 유지한다.

### 시작·가입·로그인

시작 → 가입/로그인 → 프로필 → 선택적 AI 동의 → 연인 연결 → 홈. 분석 동의는 건너뛸 수 있다. 이메일 인증·재설정 메일은 실제 인증 연결 단계에서 구현하며, 현재 가상 가입·비밀번호 형식 확인을 실제 인증으로 간주하지 않는다. 실제 비밀번호는 애플리케이션 DB에 저장하지 않는다.

오류 상태: 인증 메일 재전송, 만료 코드, 중복 가입, 로그인 실패, 비밀번호 재설정, 참여 미허용. 테스트 참여 제한 방식은 배포 전 확정한다.

### 연인 연결

초대 만들기 또는 초대 받기 → 상대 닉네임과 연결 안내 확인 → 명시적 수락 → 연결 완료.
현재 가상 흐름은 `DD-XXXXXX` 코드, 72시간 만료, 사용자당 활성 초대 1개다. 이를 실제 API의 기본안으로 이어가되 서버 발급·만료·취소·원자적 수락과 추측 시도 제한을 적용한다. 가입용 테스트 초대와 연인 연결 코드는 구분한다. 코드 저장 보호 방식과 충분한 무작위성은 실제 연결 전에 검증하며, 현재 로컬 구현을 보안 검증 완료로 보지 않는다.

실제 서비스에서는 로그인·이메일 인증 후 수락하고, 링크 방문이나 코드 조회만으로 연결하지 않는다. 한 계정은 동시에 하나의 활성 커플에만 속한다. 본인 수락·중복 수락·동시 연결·세 번째 구성원 가입을 서버에서 차단한다.

연애 시작일은 선택이며 연결일과 분리한다. 비워 두면 `null`을 유지하고 함께한 날짜를 임의로 만들지 않는다. 설정에서 추가·수정·삭제한다.

### 홈

‘오늘의 우리’ 대표 영역(두 아바타·이름·연애 시작일이 있을 때 함께한 날짜·오늘의 한 줄), 우리 리포트 바로가기, 최근 추억으로 구성한다. 같은 크기의 카드 반복보다 정보의 중요도에 따른 크기·여백·이미지 차이를 준다. 전체 디자인 개편은 별도 작업이다.

요약·리포트 미리보기는 연결 화면과 같은 상태 판단을 사용한다. 예시 검토 모드와 신규 체험을 구분하고, 신규 체험에서 AI 요약을 생성했다고 표현하지 않는다.

### 대화

상대 프로필 → 필요한 경우 접힌 코칭 안내/펼친 카드 → 대화 목록 → 표현 도움(해당 시) → 여러 줄 입력창.
접힌 코칭은 완결된 짧은 요점을 보여주고, 펼치면 근거·추천 답장을 확인한다. 추천을 선택하면 초안에 채우며 기존 초안을 덮어쓸 때 확인한다. 전송은 항상 본인이 버튼을 누른다.

입력창은 내용에 따라 일정 높이까지 늘어난 뒤 내부 스크롤한다. 일반 Enter는 줄바꿈이며 한글 조합 확정 Enter와 구분한다. 줄바꿈은 말풍선·추억 인용에도 유지한다.

첫 대화 진입은 실제 화면 배치 후 최신 메시지를 보여준다. 탭 재방문은 이전 스크롤 위치를 유지한다. 내 전송은 최신으로 이동하고, 상대 메시지 수신은 하단을 보고 있을 때만 따라간다. 과거 대화를 읽는 중에는 강제로 이동하지 않는다. 가상 화면에 구현된 규칙이며 실제 수신 연결 후 재검증한다.

메시지 상태: 전송 중 / 저장 완료 / 실패·재시도. 현재 가상 화면의 저장 완료는 로컬 저장이며, 실제 연결 후에는 서버 저장 성공을 뜻한다. 상대 읽음으로 표시하지 않는다. 읽음 표시는 초기 제외.

연결 끊김·재접속·빈 대화·AI 준비 중·분석 동의 대기·코칭 숨김·관찰 코칭 제외·AI 장애를 구분한다. 스크롤바를 숨겨도 휠·터치·키보드 스크롤은 유지한다. 검토 도구는 상단 가상 데이터 안내 줄에 두고 실제 서비스에 인증 우회 기능을 노출하지 않는다.

### 우리

상단 안내는 한 번만 표시한다: ‘대화에서 이런 모습이 보였어요. 두 사람이 느낀 것과는 다를 수 있어요.’ 카드마다 ‘미확인 가설’ 칩을 반복하지 않는다.

통계(메시지 수·대화한 날·많았던 요일)와 요일 그래프 → 대표 발견 하나 → 다른 발견 보기(접힘) 순서다. 대표 발견은 제목·짧은 흐름 도식·관찰·가능한 해석·근거 대화·작은 실천 하나로 구성한다. ‘전문가가 분석했다’고 주장하지 않고 근거와 해석을 구분한다. 관계 온도·점수·순위는 넣지 않는다.

상세에서 의견과 코칭 제외를 조작한다. 의견은 상대에게 공개되고, 코칭 제외는 양측 관련 코칭에 적용됨을 각각 안내한다. 두 사람의 의견을 정답 판정으로 합치지 않는다.

대화 부족, 분석했으나 발견 없음, AI 분석 자체 미제공은 서로 다르다. 관찰이 없어도 계산 가능한 통계는 유지한다. 신규 체험 통계는 현재 주의 저장 완료 메시지에서 계산하지만 AI 관찰은 제공하지 않는다. 예시 검토 모드의 통계·발견은 시드임을 구분한다. 화면에서 발견을 숨겨도 저장된 코칭 제외 설정은 유지한다.

### 추억

의미 있는 대화와 이미지를 돌아보는 공동 앨범이다. ‘그때의 우리’(후보가 있을 때), ‘AI가 발견한 순간’(대표 하나+더 보기), ‘우리 앨범’으로 구성한다.

- 저장 완료 말풍선 탭 → 메뉴 → 추억으로 저장 → 미리보기·선택 메모 → 저장. 저장 전에 상대에게도 보임을 안내한다.
- 원래 발신자, 대화 날짜, 저장한 사람을 구분한다. 메시지당 추억은 1개이며 직접 저장과 AI 제안 간직하기 모두 같은 중복 규칙을 쓴다.
- 저장 시점 인용 스냅샷을 보관한다. 목록은 최신 저장순이며 날짜 구분도 저장일 기준이다. 저장자만 메모 수정·삭제하고, 메모 수정은 저장일·순서를 바꾸지 않는다. 추억 삭제는 원래 메시지를 지우지 않는다.
- AI는 추억 후보를 발견하는 방향이다. 현재 모델은 사용자가 ‘간직하기’를 눌러 공동 앨범에 저장하며, 자동으로 확정 저장하지 않는다. 실제 후보 생성은 미구현이다.
- 제안 숨기기는 본인 목록에만, 간직하기는 공동 앨범에 적용된다. 삭제한 제안이 재등장해도 자동 재저장하지 않는다.
- 리마인드는 현재 저장된 추억에서만 파생한다. 닫기는 본인에게 해당 추억·마일스톤 조합만 적용한다. 예시 날짜 강제 토글은 검토 전용이다.
- 직접 저장한 앨범은 분석 동의와 무관하게 이용한다. AI 제안은 동의·AI 상태를 따른다. 현재 이미지는 라벨을 붙인 예시 SVG이며 실제 사진 업로드나 AI 생성 이미지가 아니다.

원본 메시지 삭제 시 인용 스냅샷 처리와 실제 서비스의 날짜 기준은 후속 데이터 정책에서 확정한다.

### 개인 AI 상담·설정

개인 상담은 우리 탭에서 진입하며 현재 고정 예시 답변·비영속이다. 실제 상담에 대화 기록을 넣는 범위와 동의 정책은 미정이다. 다른 사용자에게 상담 내용을 공개하지 않는다.

설정은 계정·커플 정보, AI 분석 동의, 개인 코칭 표시, 작성 중 도움을 제공한다. 실제 연결 해제·삭제·탈퇴는 서버 정책과 함께 구현한다. ‘코칭 숨기기’는 개인 화면 설정, ‘관찰 제외’는 양측 관련 코칭 중단, ‘분석 철회’는 커플 분석 중단으로 구분한다.

로그아웃·계정 전환 시 작성 중인 초안·메모·상담 요청 결과가 다음 사용자에게 섞이지 않아야 한다. 검토용 계정 전환 버튼 자체는 실제 서비스 필수 기능이 아니지만 세션 격리는 실제 로그인에도 필요한 규칙이다.

## 4. AI와 개인화 규칙

### 분석 가능 구간

두 사람 모두 동의한 시점 이후의 대화만 기본 분석 대상으로 삼는다. 과거 대화 소급 분석은 제외한다. 한 사람이 철회하면 커플 분석과 기존 관찰 활용을 중단하고, 다시 동의해도 중단 기간의 대화를 소급 분석하지 않는다. 개인 초안 분석은 작성자의 별도 설정도 필요하다.

### 실시간 코칭

최근 최대 20개 메시지와 길이 제한 내 활용 가능한 관찰을 초기 컨텍스트로 제안한다. 발화자·시간·순서를 유지한다. 전송 직후 짧은 병합 대기와 사용자별 재노출 제한을 둔다. 초기 재노출 간격은 60초, 동일 근거 중복 억제이며 테스트로 조정한다.
모든 메시지에 코칭을 강제하지 않는다. 모델은 ‘제안 없음’을 반환할 수 있다. 결과는 인사이트 1줄, 근거 1줄, 추천 답장 최대 2개, 참조 메시지 ID, 사용한 패턴 ID로 구조화한다.
상대의 마음을 판정하기보다 ‘이 대화에서는 먼저 힘들었는지 물어볼 수 있어요’처럼 행동 선택지를 제공한다. 근거 메시지가 실제 입력에 있는지 서버가 검증하고, 삭제·권한 변경·동의 철회 후에는 결과를 전달하지 않는다.
코칭은 해당 사용자만 읽을 수 있다. 공동 리포트 입력에 개인 코칭, 미전송 초안, 추천 선택 기록을 섞지 않는다.

### 작성 중 도움

설정 기본값은 꺼짐이다. 현재는 지정 예시 표현을 로컬에서 매칭하며 AI에 초안을 전송하지 않는다. 이유와 실제 대체 문장을 먼저 보여주고, 사용자가 ‘이렇게 바꾸기’를 눌렀을 때 현재 초안을 다시 확인해 매칭된 첫 부분만 교체한다. 나머지 문장·줄바꿈·다음 줄 문장부호를 보존한다. 자동 수정·자동 전송하지 않는다.

실제 AI 연결 시에는 켤 때 미전송 문장이 외부 AI로 전달될 수 있음을 설명한다. 매 키마다 호출하지 않고 입력 중단 후 평가하는 방식(초기 제안 1초)을 검증한다. 오래된 결과는 초안 버전·세션으로 폐기한다. 초안은 DB·운영 로그·공동 리포트에 저장하지 않으며 상대에게 보내지 않는다. 외부 AI 제공자의 보관 정책은 별도 확인한다. 예시 문자열 매칭을 실제 판단 규칙으로 간주하지 않는다.

### 주간 리포트와 의견·코칭 활용

커플 시간대는 초기 Asia/Seoul, 실제 주간 분석은 매주 월요일 지난 월~일을 대상으로 하는 안이다. DB 시각은 UTC로 저장하고 기간은 [시작, 종료)으로 계산한다. 현재 신규 체험의 ‘이번 주 통계’는 별개이며 실제 주간 분석 완료를 뜻하지 않는다. 초기 분석 최소 조건(양측 발화가 있는 3일 이상·합계 30개)은 아직 조정 가능한 제안이다.

v0.1의 proposed → confirmed/uncertain/disputed 및 ‘양측 맞아요 후 활용’ 모델은 폐기한다.
- 분석 동의, 관찰 의견, 코칭 활용 중단을 독립적으로 저장·판정한다.
- 의견을 안 남겼다고 동의나 거부로 간주하지 않는다. 두 사람이 의견을 남겨도 관찰이 확정 사실이 되지 않는다.
- 본인 의견만 수정·삭제할 수 있고, 공개 범위를 작성 전에 안내한다.
- 양측 분석 동의가 유효하고 제외되지 않은 관찰을 잠정적인 참고로 활용할 수 있다. 사용자는 언제든 코칭에서 제외할 수 있다.
- 한 사람이라도 제외하면 양측 관련 코칭과 해당 관찰의 실천 제안을 숨긴다. 각자 본인의 제외만 해제하며, 마지막 제외가 해제되어야 다른 조건을 재검사해 활용 가능해진다.
- 분석글에 같은 조언을 넣어 제외를 우회하지 않는다. 리포트 표시 목록이 비어도 코칭 제외는 저장된 설정을 기준으로 유지한다.
- 실제 생성 시 동의·제외·근거 유효성을 요청 전과 결과 제공 전에 검사한다. 최신 의견을 다루는 방식·관찰 갱신 주기는 후속 AI 설계에서 정하며 오래된 경향을 영구 성향으로 고정하지 않는다.

분석 철회 후 이미 저장된 관찰·의견·제외 설정의 보존/삭제/재동의 복원 정책은 미정이다. 현재 화면 차단을 데이터 삭제 완료로 표현하지 않는다.

### 모델 실행 경계

대화 내용은 분석 자료다. 대화 속 명령을 시스템 지시로 실행하지 않는다. 모델에는 DB 접근·메시지 전송 권한을 부여하지 않는다. 타 커플 데이터는 검색·프롬프트 구성 단계에서 제외한다. 결과 길이·스키마·근거를 검증하고 실패하면 조언을 표시하지 않는다.
회사에서 제공한 Claude API를 활용하는 방향이다. 정확한 모델·접속 방식·비용·보관 및 학습 이용 조건·처리 위치는 실제 연결 전에 확인한다. 키 수령만으로 실제 사적 대화 전송 조건이 검증된 것은 아니다. 이번 설계는 법률 적합성을 판정하는 문서가 아니다.

## 5. 시스템 구조

웹은 React + TypeScript로 구현되어 있다. 별도 TypeScript API 서버와 PostgreSQL을 연결한다. 정적 웹 앱을 유지하고 SSR을 필수로 두지 않는다. 로컬 API는 현재 Express 기반 코드가 작성 중이며 문서 갱신 시 실행 검증하지 않았다.

기본 흐름: 웹 화면 → API 서버 → PostgreSQL.
실제 인증 연결 후: API 서버 ↔ Cognito, 웹 ↔ 자체 세션 쿠키.
AI 후속: API 서버 → 저장된 작업 → AI 작업 처리기 → Claude API → 검증된 결과 저장.
실시간 대화 후속: 웹 ↔ 인증된 실시간 연결 ↔ API 서버. WebSocket 상세 계약은 7장 초안이다.

API와 AI 처리기는 같은 저장소·도메인 코드를 사용하되 별도 프로세스를 기준으로 한다. 작은 규모에서는 PostgreSQL 작업 테이블·잠금으로 시작하고 별도 큐 서비스는 보류한다. 메시지 저장과 필요한 작업 등록은 같은 트랜잭션으로 처리한다. 이는 후속 설계이며 현재 worker가 구현된 것은 아니다.

### 현재 단계 — 로컬 기반 구현

- 내 컴퓨터에서 API와 Docker PostgreSQL을 실행해 프로필·초대·커플 연결·동의 이력과 데이터 무결성을 검증한다.
- 로컬 인증 대체는 명시적 테스트 모드에서만 허용하고 서버·DB 포트는 루프백으로 제한한다. 배포 환경에서는 테스트 사용자 헤더로 인증할 수 없어야 한다.
- 테스트 DB는 개발 DB와 분리한다. DB 이름·접속 대상을 확인한 뒤 테스트 데이터를 초기화하며 운영·공유 DB를 테스트 대상으로 삼지 않는다.
- 현재 웹의 가상 데이터 흐름을 유지한다. 실제 인증과 프런트 API 전환은 별도 단계다.
- 이 작업에는 AWS 자원 생성이나 AWS 키가 필요하지 않다.

### AWS 기준안 — 회사 계정에서 저비용 테스트 환경

회사 AWS 사용과 PostgreSQL은 전달받은 방향이다. 리전은 서울 `ap-northeast-2`, CLI 프로필 이름은 `tunibridge`다. 기존 회사 DB를 받았다고 가정하지 않고 프로젝트용 환경을 구축하는 계획이다.

- 서버: EC2 단일 인스턴스. 현재 후보는 ARM 기반 t4g.small(2GiB)이며 실제 비용·부하·의존성 호환을 확인하고 생성한다.
- 웹/API: Nginx가 정적 웹을 제공하고 같은 출처의 `/api` 요청을 Node API로 전달한다. SPA 새로고침·직접 URL 진입을 지원한다.
- DB: 같은 EC2의 PostgreSQL. 외부에 DB 포트를 공개하지 않고 API만 연결한다. API 내부 포트도 직접 공개하지 않는다.
- 인증: Cognito User Pool을 사용한다. 회사 IAM 사용자와 DearDarling 가입자 계정은 별개다. 개발·테스트 Pool은 운영용과 분리한다.
- HTTPS: 도메인·고정 공인 IP·Nginx 인증서 자동 갱신 방식이 현재 기준안이다. 보유 도메인 사용 가능 여부를 확인하고 신규 구매는 비용 확인 후 진행한다.
- 접근: 웹 80/443, 관리용 SSH는 필요한 관리자 IP로 제한한다. DB·API 내부 포트는 인터넷 전체에 개방하지 않는다.
- 저장/백업: 암호화한 EBS, 일일 PostgreSQL 논리 백업과 제한된 보존기간의 S3, 보조 EBS 스냅샷. 데이터 디스크의 인스턴스 종료 시 삭제 방지 설정을 확인한다. 단일 서버 장애 위험을 백업만으로 없앨 수 있다고 설명하지 않는다.
- 비밀정보: AWS 개인 키를 서버에 복사하지 않는다. S3 백업·필요한 Parameter Store 조회 등은 프로젝트 범위로 제한한 인스턴스 역할을 사용한다. 암호화 파라미터의 KMS 사용 권한도 실제 구성에 맞게 확인한다.

v0.1의 Amplify·Fargate·ALB·RDS·ECR 조합은 초기 배포 기준에서 제외한다. 규모·운영 요구가 커지면 DB 분리 등으로 재검토한다.

정확한 서울 리전 견적은 배포 전에 작성한다. EC2뿐 아니라 운영체제/데이터 디스크, 공인 IP, 백업, 전송량, 인증·메일·로그·도메인·AI 비용을 포함한다. 회사 계정의 무료 제공량을 확인 없이 차감하지 않는다. 서버 중지 후에도 디스크·IP·백업 등 비용이 남을 수 있다. 예산 알림을 지출의 자동 차단으로 간주하지 않는다.

백업 보존기간은 논리 백업 7~14일·스냅샷 최근 3~7개가 현재 제안이다. 실패 감지와 별도 임시 DB 복원 시험을 수행하고, 사용자 데이터 삭제 고지와 최종 보존기간을 맞춘다.

### 앱 확장

API 버전, 데이터 형식, 오류 코드, 인증·커플 권한을 화면과 분리한다. 공유 패키지에 타입·검증 스키마·API 클라이언트를 둘 수 있다. React Native 등 앱 기술은 지금 확정하지 않는다. 모바일은 별도 Cognito 앱 클라이언트, 딥링크, 안전한 토큰 저장, 푸시·백그라운드 재동기화가 필요하며 웹 UI 전체 재사용을 보장하지 않는다.

## 6. 데이터 구조와 무결성

다음은 현재 로컬 초안과 이후 필요한 구조를 구분한 것이다. 최종 스키마는 마이그레이션과 함께 확정하며 이 목록을 전부 구현 완료로 읽지 않는다.

현재 로컬 마이그레이션 초안:
- `users`: id, email, nickname, avatar_emoji, couple_id, analysis_consent, created_at 등. 비밀번호 제외. 현재는 로컬 테스트 사용자이며 Cognito 식별자 연결은 후속이다.
- `couples`: id, connected_at, relationship_start_date. 연결일과 선택적 연애 시작일 분리.
- `invites`: 코드, 발급자·수락자, 상태, 만료·수락 시각. 사용자당 pending 초대 1개를 제한하며 만료 상태 전환과 동시 수락을 처리한다.
- `consent_events`: 사용자·동의 여부·변경 시각. 실제 분석 전에는 적용 범위·정책 버전·커플 및 유효 구간을 판별할 정보를 보강한다.

실제 인증 연결 단계:
- `users`에 Cognito `sub` 유일 매핑을 추가한다. 이메일만으로 기존 사용자를 임의 연결하지 않는다.
- `sessions`: 사용자, 세션 식별자, 생성·만료·철회 시각. 필요한 refresh token은 암호화해 제한적으로 보관한다. 원문 토큰을 로그에 남기지 않는다.
- 요청 제한 카운터 등 인증·초대 남용 방지 데이터를 둔다.

실제 대화·AI·추억 연결 단계:
- `messages`: 커플·발신자·client_message_id·sequence·본문·생성/삭제 시각. 발신자별 요청 ID 및 커플별 sequence 유일 제약.
- `coach_suggestions`: 커플·개인 수신자·내용·대안·근거 메시지/관찰 ID·분석 버전·유효기간.
- `weekly_reports` / `pattern_observations`: 기간·관찰·대표 발견·근거·해석·버전. confirmed 투표 모델을 도입하지 않는다.
- `pattern_opinions`: 관찰·작성자·의견·수정 이력. 본인 수정/삭제 권한.
- `pattern_coaching_opt_outs`: 관찰·선택 사용자. 남아 있는 제외가 하나라도 있으면 양측 코칭 제외.
- `memories`: 커플·원본 메시지 식별자·인용 스냅샷·원발신자·대화 시각·저장자·저장 시각·메모. 커플 내 같은 원본 메시지 중복 저장 방지.
- 추억 제안·개인 숨김·리마인드 닫기: 공동 제안과 사용자별 선택을 분리한다.
- `jobs`: 작업 유형·소속·입력 경계·분석 버전·상태·재시도·lease·중복 방지 키. 원문 복제 최소화.
- `product_events`: 허용된 최소 메타데이터만. 대화·초안 원문 제외.
- `deletion_requests`: 범위·요청자·진행·완료 시각. 재실행 가능한 삭제 작업.

v0.1의 `couple_members` 별도 테이블은 필수 확정 구조가 아니다. 현재 `users.couple_id` 구조에서도 동시 연결 시 두 명 제한과 한 사람의 중복 커플 소속 금지를 트랜잭션·잠금·조건부 갱신으로 보장해야 한다. 단순 프런트 검사나 외래키만으로 두 명 제한이 보장되지는 않는다.

모든 조회·수정은 인증 사용자 → 현재 커플 소속 → 리소스 소속 → 개인 소유/수신자 순으로 검사한다. URL의 ID만으로 접근할 수 없다. DB 제약과 서비스 검증을 함께 사용한다. 로컬 테스트의 가상 인증은 실제 권한 검증 완료를 대체하지 않는다.

## 7. API·실시간 계약 초안

아래 `/v1` 경로는 논리 계약 초안이다. 실제 로컬 라우트와 공개 `/api` 프록시 경로는 구현 시 일관되게 매핑해 기록하며, 이미 연결된 경로라고 가정하지 않는다.

실제 웹 인증 기준안은 서버가 Cognito 인증을 처리하고 자체 HttpOnly·Secure·SameSite 세션 쿠키를 발급하는 방식이다. 매 API 요청에서 자체 세션의 만료·철회와 사용자 권한을 확인한다. 상태 변경 요청은 Origin 및 CSRF 방어를 적용한다. 같은 출처의 웹/API 배치를 기준으로 한다. Cognito 토큰을 검증할 때 서명·발급자·대상·만료·용도를 확인한다.

로그아웃은 해당 앱 세션을 즉시 무효화한다. 전체 로그아웃·비밀번호 재설정 후에는 이전 앱 세션을 모두 차단한다. Cognito 후처리 실패가 앱 세션 차단을 취소하지 않게 한다. `GlobalSignOut`은 access token으로 호출하며 refresh token을 직접 전달하지 않는다. 실패 후 지연 정리는 이전 refresh token 대상 `RevokeToken` 등으로 설계하고 그사이 새로 로그인한 세션까지 전체 종료하지 않도록 검증한다. 세션·토큰 수명과 삭제 주기는 실제 인증 연결 시 확정한다.

향후 모바일 인증 어댑터는 별도로 설계한다. 웹 쿠키 세션과 동일한 로그아웃·권한 경계를 보장해야 한다.

- GET /v1/me: 사용자·커플·동의 상태.
- POST /v1/invitations, POST /v1/invitations/accept: 초대 생성·원자 수락.
- POST /v1/couple/consents: 본인 동의 변경, scope와 문서 버전 기록.
- GET /v1/messages?afterSequence=&limit=: 소속 커플 메시지 증분 조회. 이전 기록은 beforeSequence 사용.
- POST /v1/messages: clientMessageId, body. sender와 couple은 서버가 결정.
- GET /v1/coaching: 본인 최신 유효 코칭.
- POST /v1/draft-assessments: 초안 버전과 본문, 저장하지 않는 분석.
- GET /v1/reports, GET /v1/reports/:id: 공동 리포트.
- POST /v1/patterns/:id/opinions 및 본인 의견 수정·삭제: 공개 안내와 작성자 권한 검증. version 충돌은 409.
- PUT /v1/patterns/:id/coaching-opt-out: 본인 제외 선택·해제. 양측 코칭에 반영.
- GET/POST /v1/memories 및 본인 저장 추억 수정·삭제: 공동 조회, 메시지 중복 저장 방지.
- 추억 제안 숨김·간직하기, 개인 상담 API는 후속 계약으로 구체화한다.
- POST /v1/couple/disconnect, POST /v1/deletion-requests: 연결 종료·삭제.
- POST /v1/events: 허용된 제품 이벤트만 수집.

에러 규약: 401 인증 필요, 403 접근 불가, 404 리소스 미노출, 409 상태 충돌, 422 입력 오류, 429 제한, 503 일시 장애. requestId로 오류를 찾고 원문을 로그에 넣지 않는다.

WebSocket은 인증 후 현재 커플과 개인 채널에 서버가 배정한다. 클라이언트가 임의 room에 가입할 수 없다. 이벤트는 message.available, coach.available, report.available, consent.changed, couple.disconnected. 본문 대신 ID/sequence 중심으로 보내고 API 재조회 시 권한을 다시 확인한다. 세션 만료·철회·연결 해제 시 구독도 끊는다.
알림은 저장소가 아니다. 재접속 시 마지막 sequence 이후를 DB에서 가져온다. API 여러 인스턴스 운영 전 인스턴스 간 알림 전달을 추가해야 하며, 초기에도 재조회로 누락을 복구한다.

## 8. 실패와 동시성 처리

메시지 전송: 권한 검사 → 커플 sequence 할당 → DB 저장 + 작업 등록 → 저장 완료 응답 → 실시간 알림. 응답 유실 후 같은 clientMessageId로 재시도해도 한 건만 만든다.
AI: 작업 획득 → 양측 동의/epoch 재확인 → 최소 컨텍스트 구성 → 모델 호출 → 결과 검증 → 동의/epoch 재확인 → 저장·알림. 이미 외부에 전송된 요청은 철회로 회수할 수 없지만 결과 저장·제공과 후속 호출은 차단한다.
작업은 중복 실행될 수 있다고 가정한다. dedupe_key, lease, 최대 3회 재시도·지수 지연, 실패 상태·관리자 재실행으로 처리한다. 모델 요청 자체의 중복 과금 가능성도 비용 지표에 반영한다.
AI 실패 시 메시지는 정상 전송하고 ‘대화 도움을 잠시 사용할 수 없어요’로 표시한다. 가짜 조언을 대체 응답으로 만들지 않는다.

## 9. 연결 종료·삭제 정책

연결 해제 후 이전 커플의 접근·전송·분석을 차단하고 이전 기록·관찰을 새 커플에 승계하지 않는 원칙은 유지한다. 다만 공유 대화·추억을 누가 어떤 범위로 보존/삭제할지는 실제 참여자 모집 전에 확정한다. 현재 검토 도구의 연결 해제·가상 데이터 초기화를 실제 서비스 탈퇴 정책으로 간주하지 않는다.

v0.1의 ‘해제 시 공유 데이터 삭제’, ‘7일 이내 제거’, ‘백업 7일’은 확정 정책이 아니었다. 최근 백업안은 7~14일 등이므로 최종 삭제 기한·백업 소거 시점과 안내를 함께 확정한다. 삭제 요청 후 서비스 조회 차단, 원문·추억 스냅샷·파생 결과·대기 작업 제거, 복구 시 삭제 이력 재적용을 설계한다. 단순 논리 삭제를 완전 삭제로 설명하지 않는다.

분석 철회는 메시지·직접 저장 앨범 삭제와 다르다. 즉시 추가 분석·관련 결과 제공을 중단하되 기존 관찰·의견·제외 선택의 보존/삭제/재동의 복원은 미정이다. 원본 메시지 삭제 시 독립 저장된 추억 인용을 어떻게 처리할지도 확정해야 한다. 외부 AI에 이미 전송된 내용은 철회로 회수할 수 있다고 설명하지 않는다.

운영자 화면에 대화 원문 열람 기능을 만들지 않는다. 인프라 관리자에게 기술적 접근이 불가능하다고 주장하지 않는다. 테스트 종료 후 정리 일정과 실제 AI 제공자의 보관 범위도 참여 전에 안내한다.

## 10. 검증 기준

아래는 단계별 완료 기준이며, 현재 전부 통과한 상태를 뜻하지 않는다.

로컬 기반 검증: 별도 테스트 DB, 프로필 저장·조회, 만료·취소·중복·동시 초대 수락, 원자적 롤백, 동의 기본 꺼짐·이력, 테스트 인증의 배포 환경 차단.

실제 서비스 연결 후 필수 통과:
- 서로 다른 브라우저의 두 계정이 가입·연결·전송·재접속할 수 있다.
- 제3의 계정은 HTTP와 WebSocket 모두 타 커플 대화·개인 코칭에 접근하지 못한다.
- 중복 초대 수락·동시 연결·전송 재시도에도 구성원과 메시지가 중복되지 않는다.
- 한쪽만 AI 동의했거나 작업 중 동의를 철회하면 결과가 제공되지 않는다.
- 의견 유무와 관계없이 관찰을 확정 사실로 표시하지 않는다. 한쪽 제외로 양측 관련 코칭·실천이 가려지고 본인 선택만 해제할 수 있다.
- 관찰 제외·근거 삭제·동의 철회 이후 부적절한 기존 코칭이 재사용되지 않는다. 표시 목록이 비어도 제외는 유지된다.
- AI 장애·재시작·네트워크 단절 후 채팅과 작업이 복구된다.
- 애플리케이션 DB에 비밀번호·미전송 초안 원문이 남지 않는다. 필요한 인증 토큰은 암호화된 제한 저장만 허용하고 로그·브라우저 코드·저장소에 비밀정보가 노출되지 않는다.
- 로그아웃·비밀번호 재설정 후 기존 세션이 즉시 거부되며, 토큰 정리 재시도가 신규 세션을 종료하지 않는다.
- 추억 중복 저장·작성자 권한·개인 숨김·세션 전환 시 초안 격리가 서버 연결 후에도 유지된다.
- 연결 종료·삭제·백업 복구 후 접근 차단과 삭제 재적용이 검증된다.

성능 목표 제안: 테스트 조건 동시 20명, 메시지 서버 저장 p95 1초 이내, 온라인 상대 화면 반영 p95 2초 이내, 코칭 p95 8초 이내. 측정 전 보장값이 아니며 실제 모델·리전으로 조정한다.

제품 측정:
- 추천 선택률 = 추천을 선택한 코칭 노출 건수 / 추천이 실제 노출된 코칭 건수.
- 추천 활용 전송률 = 추천을 선택한 뒤 전송한 코칭 건수 / 추천이 노출된 코칭 건수. 원문 비교 대신 suggestionId 연결로 측정하며 편집 후 전송도 구분한다.
- 코칭 도움 평가·불편 신고, 관찰 의견 참여율·코칭 제외율, 커플 기준 주간 사용, 초대 완료율을 함께 본다.
- 회사 문서의 30%는 검증할 가설이다. 선택률 하나만으로 코칭의 가치나 관계 개선을 입증하지 않는다. 표본 수와 관찰 기간을 함께 보고한다.

## 11. 구현 순서와 완료 조건

1. 화면 흐름 — 가상 데이터로 홈·대화·우리·추억·설정·상담·온보딩을 구성하고 검토한 상태다. 전체 디자인 개편은 필요 시 별도로 진행한다.
2. 로컬 기본 서비스 — 현재 작업. API·PostgreSQL 마이그레이션, 테스트용 사용자, 프로필, 커플 연결·초대, 동의 이력, 동시성·권한 테스트를 구현한다. 실제 Cognito·AWS·AI는 이 단계 완료 조건이 아니다.
3. 실제 인증 연결 — 개발용 Cognito, 자체 세션, 이메일 인증·로그아웃·재설정을 검증한다. 웹 API 전환을 준비하되 기존 가상 화면은 별도 작업에서 전환한다.
4. 조기 AWS 연결 시험 — 비용·권한·도메인·백업을 확인한 뒤 회사 AWS에 작은 환경을 구축한다. 인증·API·DB를 HTTPS로 연결하고 기존 웹을 실제 API에 전환해 두 기기 가입·연결·재로그인을 검증한다. 가상 로그인·검토 데이터가 실제 서비스로 유입되지 않도록 분리한다. 전체 AI 완성까지 인프라 검증을 미루지 않는다.
5. 실제 대화·추억 저장 — 메시지 저장·수신·재접속·중복 방지와 직접 저장 앨범을 연결한다. 기존 화면의 스크롤·초안 보존·세션 격리를 재검증한다.
6. AI 코칭·개인화 — 가상 대화 평가와 모의 계약 검증 후 회사 Claude API를 연결한다. 동의·관찰·의견·제외를 반영하고 주간 작업·추억 후보·개인 상담은 각각 범위를 구분해 구현한다.
7. 테스트 준비 — 실제 2계정 및 제3자 접근 차단, 삭제 정책·복구·비용 제한·참여 안내를 확인하고 사내/지인을 초대한다.

기존 저장소 `apps/web`, `apps/api`, `apps/worker`, `packages/contracts`, `packages/domain`, `infra`, `docs`를 활용한다. 단계마다 실행법·환경변수 예시·마이그레이션·검증 결과·미구현 범위를 기록한다. README가 작업 중 코드보다 늦게 갱신될 수 있으므로 완료 보고 시 실제 상태와 맞춘다. 비밀 값은 예시 파일에 넣지 않는다.

브랜치 생성·이동이 필요하면 먼저 이유를 설명하고 사용자의 결정을 따른다. 커밋·푸시는 요청 시 수행한다. 문서 갱신을 AWS 생성·배포·데이터 삭제의 승인으로 해석하지 않는다. 구현 진행 중인 파일은 다른 작업자가 동시에 수정하지 않는다.

## 12. 구현을 막지 않는 미확정 사항과 배포 전 확인 사항

이미 정리된 방향:
- 웹 우선·모바일 브라우저 중심, 4탭과 별도 설정·상담 진입점.
- 회사 AWS에서 프로젝트 환경 구축, PostgreSQL, 서울 `ap-northeast-2`.
- EC2 단일 서버 기반의 저비용 초기 배포안, Cognito 인증 방향.
- 회사에서 AWS 액세스 키·시크릿 키와 Claude API를 받았다는 사용자 설명. 이 문서에 실제 값은 기록하지 않는다.
- AWS CLI 프로필은 `tunibridge`. 키 보유는 모든 자원 생성·변경 권한 보유를 뜻하지 않는다. 콘솔 URL은 접속 주소이며 DB 주소나 배포 서버 주소가 아니다.

로컬 개발을 막지 않는 항목: 정확한 월 견적·예산 상한, HTTPS 도메인, 관리자 역할 생성, 개발용 Cognito Pool, 실제 AI 모델·주간 분석 최소 기준·빈도. 필요한 단계에서 결정한다.

실제 AWS 생성/데이터 사용 전에 확인:
- 서버·디스크·백업·IP·인증·메일·AI를 포함한 비용과 예산 상한. 필요한 자원별 승인 후 생성.
- 프로젝트 자원 식별과 회사 기존 자원 분리, 실제 생성 권한, 도메인·인증서·백업 경로.
- 인스턴스 역할의 최소 S3/파라미터 접근과 필요한 암호화 키 권한. 개인 AWS 키의 서버 복사 금지.
- 실제 이메일 인증·재설정 발송 구성과 제한. SES 사용 여부는 선택한 발송 방식에 따라 확인하며 로컬 구현의 선행 조건으로 두지 않는다.
- AI 제공자의 데이터 처리 조건, 테스트 참여 제한, 공유 데이터 삭제·보관·복구 정책.

전달받은 IAM 정보: 본인 ChangePassword 허용, CreateRole·AttachRolePolicy·PassRole·AssumeRole 제한, 본인 액세스 키 생성과 MFA 등록도 제한. 실제 계정에 조회해 재검증한 결과는 아니다. 키 생성 제한은 CLI 사용 자체의 금지가 아니다. 이미 발급받은 키로 허용된 작업만 수행할 수 있다.

관리자에게는 부족한 특정 역할·리소스 권한만 요청하고 광범위한 관리자 권한을 기본 요청하지 않는다. MFA 등록은 관리자 지원 대상이다. 사용자는 키·비밀번호를 대화/스크린샷으로 공유하지 않고 본인 컴퓨터에 직접 설정한다. 공개·권한 확대·회사 자원 삭제·비용 발생 조작은 실행 전에 범위와 영향을 설명한다.

이번 문서 갱신에서는 AWS 로그인·자원 생성·배포·DB 변경·AI 원문 전송을 수행하지 않았다. 저장소 문서와 작성 중 파일의 확인만 수행했다.

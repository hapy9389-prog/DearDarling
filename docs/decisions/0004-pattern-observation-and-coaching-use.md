# 0004 — 패턴 관찰과 코칭 활용 모델

날짜: 2026-09-09

## 배경

"주간 리포트에서 관찰된 소통 패턴을 두 사람이 모두 '맞아요'로 확인해야 코칭에 활용한다"는
초기 방식(외부 "DearDarling 요구사항 및 설계 v0.1")을 **폐기**한다.

- 무응답이 사실상 '거부'로 작동해 대부분의 관찰이 사장된다.
- '맞아요'가 관찰을 '확정된 사실'처럼 보이게 만들어, 이후 코칭이 상대의 성향·감정을 단정하는
  근거로 쓰이기 쉽다.

대신 AI가 관찰한 패턴을 **미확인 가설**로 먼저 보여주고, 사용자는 필요할 때만 의견을 덧붙이거나
그 관찰의 코칭 활용을 중단한다.

## 결정

### 1. 세 가지를 서로 독립적으로 관리한다

| 대상                                            | 저장 위치                                    | 무응답일 때                              |
| ----------------------------------------------- | -------------------------------------------- | ---------------------------------------- |
| **분석 동의**(`analysisConsent`, 사용자별)      | `userKey(userId, 'settings')` (기존)         | 변화 없음. 둘 다 동의해야 커플 분석 활성 |
| **관찰에 대한 의견**(`opinions[]`, 관찰별)      | `coupleKey(coupleId, 'patternObservations')` | 의견 없음 = 미확인 가설                  |
| **코칭 활용 중단**(`coachingOptOuts[]`, 관찰별) | 같은 저장소                                  | 중단 아님 (단, '동의'도 아님)            |

의견을 남긴다고 분석에 동의하는 것도, 코칭 활용을 중단하는 것도 아니다. 반대도 마찬가지다.
세 가지는 화면·저장·계산 어디에서도 서로를 유발하지 않는다.

### 2. 관찰은 계속 미확인 가설이다

- 무응답 관찰을 '동의함' 또는 '확인된 패턴'으로 표시하지 않는다. 기본 라벨은 **미확인 가설**.
- 의견을 덧붙여도 관찰이 '확정'되지 않는다.
- **두 사람이 모두 의견을 남겨도** 관찰은 미확인 가설이다. 이 경우 화면은 "두 사람이 남긴 의견"으로
  **중립적으로** 표시하고, 두 의견이 '다르다/맞다'를 판정하지 않는다. 의견을 남겼다는 사실만으로
  "해석이 갈렸다"고 라벨링하지 않는다.
- 이후 코칭은 관찰을 항상 **가설**로만 다룬다. 상대의 성향·감정으로 단정하는 문구
  ("상대는 ~한 사람이에요")를 쓰지 않고, "~한 경향이 관찰됐어요(아직 확인되지 않음)"처럼 쓴다.

### 3. 의견

- AI 관찰을 덮어쓰지 않고 관찰 아래에 **작성자 이름과 함께 별도로** 쌓인다.
- **본인 의견만** 수정·삭제할 수 있다(`patternService`가 `authorId`로 검증).
- 의견 입력 화면에 들어가기 전에 "입력한 의견은 상대에게도 공유돼요"를 안내한다.
- 두 사람의 의견은 하나로 합치거나 정답을 고르지 않고 **나란히** 보여준다.

### 4. 코칭 활용 중단

- 한 사람이라도 '이 관찰을 코칭에 사용하지 않기'를 선택하면, 그 관찰은 **양측의 이후 코칭에서
  모두 제외**된다(`isExcludedFromCoaching` = `coachingOptOuts.length > 0`).
- 다른 사람이 그 선택을 임의로 해제할 수 없다. 각자 **자신의 중단 선택만** 철회할 수 있다.
- 상태 라벨상 '코칭에서 제외됨'이 의견 라벨보다 우선 표시된다(0006에서 문구를 '제외됨'으로 통일).

### 5. 예시 관찰 ↔ 예시 코칭 연결 (화면 검토용, Phase C 필수)

실제 AI 코칭 생성은 아직 없지만, 코칭 활용 중단이 **양측 코칭에 실제로 반영되는지**를 가상 화면에서
검토할 수 있어야 한다.

- 시드 코칭 제안(`SEED_COACHING_SUGGESTION`)에 `sourcePatternId`를 추가해 시드 관찰 1건과 연결한다.
- 그 관찰이 (민준이든 서연이든 누구든) 코칭 활용 중단 상태이면 `coachingService.getSuggestion`이
  `{ status: 'withheld-optout' }`를 반환한다.
- 대화 화면 코칭 카드는 제안 대신 "이 관찰을 코칭에 사용하지 않기로 해서 관련 코칭을 표시하지
  않아요"를 보여준다. 두 계정 모두에서 동일하게 동작한다.

**대화 화면 코칭 영역 우선순위**(0002 §3 갱신, 0006에서 구현):
분석 동의·철회 → AI 상태(준비 중/장애) → 코칭 카드 숨김(개인 설정) → **관찰 코칭 활용 중단** → 실제 제안.

`getSuggestion`가 `excludedPatternIds`를 받아, 제안의 `sourcePatternId`가 그 목록에 있으면
`{ status: 'withheld-optout' }`을 돌려준다. `PatternProvider`(전역 컨텍스트)가 '우리' 탭과 상시
마운트된 대화 화면에 같은 상태를 준다.

### 6. 분석 철회 후 데이터 정책은 미정

한쪽이라도 AI 분석을 철회하면 홈 요약·주간 리포트·패턴 기반 코칭을 **화면에서 중단**한다.
철회 이후 이미 쌓인 관찰·의견·중단 선택을 **보존할지, 삭제할지, 재동의 시 어떻게 복원할지는
아직 정하지 않았다**(0005). 화면 검토 단계에서는 가상 데이터(localStorage)의 화면 차단만
확인하며, 데이터를 지우지 않는다고 해서 "재동의 시 자동 복원"을 정책으로 확정하는 것은 아니다.

### 7. 화면 검토 범위

가상 화면에서 다음 상태를 모두 검토할 수 있어야 한다(시드 관찰을 상태별로 미리 세팅):
관찰만 있는 상태 / 한쪽 의견 추가 / 두 사람이 의견을 남긴 상태 / 코칭 활용 중단.
DevPanel 계정 전환으로 양측 시점을 확인한다.

## 0002와의 관계

대화 화면 코칭 영역 우선순위(0002 §3)에 "관찰 코칭 활용 중단"이 한 단계 추가된다.
이 단계는 **0006에서 구현**됐다.

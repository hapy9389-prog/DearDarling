# 0006 — '우리' 탭(주간 리포트·패턴 관찰)과 AI 개인 상담

날짜: 2026-09-09

## 배경

`week` 탭(자리표시자)에 0004의 소통 패턴 관찰·의견·코칭 활용 중단 모델을 처음으로 화면에 올리고,
같은 탭에 개인 상담 진입점('AI에게 물어보기')을 둔다. 여전히 가상 데이터로만 동작한다.

## 결정

### 1. 탭 라벨을 '우리'로 바꾼다 (내부 id는 `week` 유지)

주간 리포트 + AI 상담을 아우르므로 하단 탭 라벨은 `이번 주 우리` → **`우리`**. `AppTab` id·저장 키·
`NavigationContext`의 화면 전환 로직은 그대로 `week`다. 홈의 관련 문구와 관련 테스트도 함께 고쳤다.

### 2. AI 상담은 탭이 아니라 하위 화면(`screen === 'ask'`)

설정과 같은 패턴이다. `AppScreen = AppTab | 'settings' | 'ask'`. ← 버튼으로 '우리' 탭으로 돌아오고,
`ask` 화면에서는 어떤 하단 탭도 `aria-current="page"`가 아니다. `AppShell`이 조건부로 렌더하므로
열 때마다 새로 마운트된다.

### 3. 소통 패턴 관찰 카드 — 처음 화면에서 읽을 양을 줄인다

처음 화면에는 **관찰 한 줄 + 제안 한 줄 + '자세히 보기'**만 보여준다. 근거·의견·의견 작성·코칭
제외 조작은 카드별 펼침 영역에 둔다.

- 상태 칩(`미확인 가설` / `코칭에서 제외됨`)은 접힌 상태에서도 항상 보인다 — **제외된 카드는
  접혀 있어도 '코칭에서 제외됨'을 표시**하고, 접힌 요약에서 제안을 가린다.
- 잠정 관찰 안내는 매 줄 반복하지 않는다. 섹션 헤더에 한 번("아직 확인되지 않은 잠정 관찰이라
  상대의 성향이나 감정을 단정하지 않아요") + 카드마다 짧은 `미확인 가설` 칩. 관찰 문구 자체는
  확정된 사실처럼 들리지 않게 관찰형으로만 쓴다(시드에서 "(아직 확인되지 않음)" 꼬리표 제거).
- 의견을 두 사람이 남겨도 라벨은 `미확인 가설` 그대로. `코칭에서 제외됨`이 그보다 우선
  (`observationStatusLabel`).
- 메시지 수·요일별 막대·하이라이트는 카드들 아래 **접힌** `이번 주 통계 · 보조 참고` 섹션에 두고,
  펼쳐야 보인다.
- AI 상담 진입점은 헤더의 **작은 버튼**('AI에게 물어보기') 하나. 상세 설명은 상담 화면에 있다.

### 4. 의견 — 각자 남기고, 본인 것만 수정·삭제

- `의견 남기기`(펼침 영역)를 누르면 입력창이 열리고, **그 위에 "입력한 의견은 상대에게도
  보여요"를 먼저 보여준다**. 입력 전에는 이 안내가 화면에 없다.
- 두 사람 의견은 작성자 이름과 함께 나란히(`두 사람이 남긴 의견`). "맞다/갈렸다"를 판정하지 않는다.
- `patternService`가 `authorId`로 검증한다 — 남의 의견을 수정·삭제하면 에러.
- 의견을 남기지 않았다고 "동의"로 취급하지 않는다(라벨 불변, 저장도 없음).
- **계정 격리**: 의견을 작성·수정하는 중에 계정을 전환하면 입력창과 초안을 버린다 — 한 사람이
  쓰던 내용이 다른 계정 이름으로 저장되지 않게(`ChatPage`가 초안을 비우는 것과 같은 규칙).

### 5. 코칭 활용 중단 — 한쪽만 제외해도 양측에서 빠지고, 본인 것만 해제

- 토글 위에 **범위 안내**를 항상 보여준다: "코칭에서 제외하면, 두 사람의 대화 코칭과 이 리포트의
  관련 제안에 사용하지 않아요. 한 명이라도 제외하면 두 사람 모두에게 적용되고, 각자 자신의 제외만
  해제할 수 있어요."
- 한 명이라도 `coachingOptOuts`에 있으면 `isExcludedFromCoaching`이 참 → **그 카드의 '도움이 될
  제안'을 가리고** "관련 제안을 표시하지 않아요"로 대체한다. 관찰·근거·의견·통계는 유지.
- 상대가 제외한 관찰에는 `내 제외 해제` 버튼이 없다(읽기 전용 안내). 나도 제외를 추가할 수는 있고,
  `revokeOwnOptOut`은 **자신의 항목만** 제거한다. 두 사람 모두 제외했으면 한 명이 해제해도 계속 제외.

### 6. 예시 관찰 ↔ 예시 코칭 연결 (0004 §5 필수 항목)

- `SEED_COACHING_SUGGESTIONS`는 **두 계정 각각의 제안**(민준·서연)을 담고, 둘 다
  `sourcePatternId = 'pat-1'`로 같은 관찰에 연결한다. `pat-1`은 기본 시드에서 **제외되지 않은**
  관찰이라 기본 상태의 대화 코칭은 그대로 동작한다(기존 대화 화면 테스트 회귀 유지).
- `coachingService.getSuggestion`은 `recipientId`로 제안을 찾고, `excludedPatternIds`를 받는다.
  제안의 `sourcePatternId`가 그 목록에 있으면 `{ status: 'withheld-optout' }`을 돌려준다. 한쪽이
  `pat-1`을 제외하면 **두 계정의 제안이 모두** 빠진다 — 대화 화면 코칭 영역은
  "이 관찰을 코칭에 사용하지 않기로 해서 관련 코칭을 표시하지 않아요."를 보여준다.
- 대화 화면은 상시 마운트라(0003 §3) '우리' 탭에서의 토글이 스스로 반영되지 않는다. 그래서
  `PatternProvider`(전역 컨텍스트, `SettingsContext`와 같은 이유·같은 패턴)가 두 화면에 같은 상태를
  준다. `ChatPage`의 코칭 계산 이펙트는 `excludedPatternIds`를 의존성에 포함한다.
- **대화 화면 코칭 영역 우선순위**(0002 §3 / 0004 §5 갱신, 이제 구현됨):
  분석 동의·철회 → AI 상태(준비 중/장애) → 코칭 카드 숨김(개인 설정) → **관찰 코칭 활용 중단** → 실제 제안.
  `coachingVisible`(숨김)이 `ChatPage`에서 서비스 호출보다 먼저 확인되므로 이 순서가 유지된다.

### 7. AI 개인 상담 — 이번 범위와 이후 범위

|      | 이번 단계(구현)                                                                                          | 이후 실제 AI 연결(범위 밖)                                        |
| ---- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 답변 | 시드 예시 질문 → 고정 답변, 가상 지연(600ms). 화면에 "화면 검토용 예시이며 실제 AI 답변이 아닙니다" 표시 | 실제 LLM 호출, 커플 대화·리포트 맥락을 반영한 개인화 답변         |
| 입력 | 예시 질문 탭만. 자유 입력창 비활성 + "실제 AI 연결 이후 지원" 안내                                       | 자유 입력 + 스트리밍·오류·재시도                                  |
| 저장 | 비영속(화면 안에서만). 계정 전환 시 초기화                                                               | 개인별 상담 기록 영속(비공개), `userKey` 범위                     |
| 공유 | 진입점만 — 상대·공유 리포트에 자동 공개 안 됨                                                            | 특정 인사이트를 사용자가 **명시적으로** 공유 리포트에 올리는 선택 |
| 접근 | 리포트 상태 분기 **바깥** — 분석 철회·대화 부족에서도 접근 가능                                          | 실제 대화를 분석하는 상담의 동의 정책은 **이후 결정**(0005 계열)  |

- **계정 격리**: 계정을 전환하면 상담 내역을 비우고 **세션 번호**를 올린다. 진행 중이던 요청은
  자신이 시작된 세션 번호를 기억해 뒀다가, 완료 시점의 세션과 다르면 답변도 대기 해제도 버린다.
  계정 ID만 비교하면 민준→서연→민준으로 돌아왔을 때 이전 민준 세션의 늦은 답변이 초기화된 화면에
  섞인다 — 세션 번호는 "초기화 전후"까지 구분한다.

### 8. 상태 처리

'우리' 탭 리포트 본문은 대화 화면 코칭 영역과 같은 우선순위로 분기한다:

| 조건                                  | '우리' 탭                                                             |
| ------------------------------------- | --------------------------------------------------------------------- |
| 커플 분석 비활성(한쪽이라도 철회)     | "리포트와 패턴 관찰이 중단됐어요" + 설정 링크. self/partner 사유 구분 |
| `scenario === 'ai-warming-up'`        | "이번 주 리포트를 준비하고 있어요"                                    |
| `scenario === 'ai-failure'`           | "지금은 리포트를 불러올 수 없어요"                                    |
| `scenario === 'empty'`(또는 관찰 0건) | "리포트를 만들 만큼 대화가 많지 않았어요"                             |
| 그 외                                 | 리포트 본문(관찰 카드 + 통계)                                         |

- `coachingVisible`(코칭 카드 숨김)은 개인 표시 설정이라 이 리포트에 **영향을 주지 않는다**(0003 §4).
- AI 상담 진입점은 이 분기 바깥에 있어 모든 상태에서 보인다.

## 0004에서 미정으로 남은 항목

- 분석 철회 후 관찰·의견·중단 선택의 보존·삭제·복원 정책은 여전히 미정(0005). 화면 검토 단계에서는
  가상 데이터(localStorage)의 화면 차단만 확인하고, 데이터를 지우지 않는다.
- 관찰에서 실제 코칭 문구를 생성하는 로직은 후속 작업(0005).

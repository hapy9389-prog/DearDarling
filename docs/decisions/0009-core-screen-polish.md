# 0009 — 가입·로그인 전 핵심 화면 경험 보완

날짜: 2026-09-10

## 배경

가입·로그인·연인 연결 화면(0005)으로 넘어가기 전에, 원본 프로토타입
(`relationship_ai_messenger_prototype.html`)이 전하는 두 감성을 현재 구현에 더 잘 드러낸다:

1. **둘만의 공간** — 홈이 비슷한 크기의 테두리 상자 목록이라 "우리"라는 느낌이 약했다.
2. **묻기 전에 먼저 건네는 코칭** — 접힌 코칭 카드가 "새로운 대화 힌트가 있어요"라는
   빈 안내라, 펼치기 전에는 도움이 되지 않았다.

원본을 복제하지 않는다. 4탭 구조(홈·대화·우리·추억), AI 개인 상담을 '우리' 안에 두는 구조,
관계 온도·점수 없음(0005 보류), 대화 중간 인라인 코칭 제외는 그대로 유지한다.
실제 AI·인증·DB·AWS·사진/영상 업로드는 이번에도 연결하지 않는다.

### 착수 시점의 코드↔문서 차이

- `README.md`가 추억 탭을 "진행 중"으로 표기 → 실제로는 0008로 구현 완료. 갱신함.
- `0003` 상태표가 설정의 '작성 도움'을 "구현 완료"로 표기 → 실제로는 `disabled` + "준비 중"
  배지의 자리표시자였고 `UserSettings.draftHelpEnabled` 필드는 아무도 읽지 않았다. 이 결정으로
  화면 검토용 예시를 체험 가능하게 만들고 상태표를 갱신함.

## 결정

### 1. 접힌 코칭 카드 — 요점 한 줄

- `CoachingSuggestion.headline?`(선택, 한 문장, 좁은 화면에서도 완결되는 짧은 문장)을 추가.
  접힌 카드는 `headline ?? insight`를 보여준다. `headline`이 있으면 자르지 않고, 없는 과거
  데이터는 `insight`를 최대 2줄로 방어한다. **긴 문장을 두 줄로 자르는 방식이 아니다.**
- 펼침은 그대로: `insight`(전체) + `근거: evidenceText` + 추천 답장 목록.
- 접힌 버튼에 `aria-label="코칭 카드 펼치기"` — 계정에 따라 문구가 달라도 테스트가 안정적으로 잡는다.
- 바이올렛 톤, 목록 위 얇은 흐름 배치(덮지 않고 밀어냄), 추천 답장은 초안에만 반영, 자동 전송 없음,
  분석 동의·철회 / 코칭 숨김 / 관찰 제외 / 준비 중·장애 처리 — 모두 유지.

### 2. 메시지 입력 — 여러 줄

- `<input>` → `<textarea rows={1}>` + `min-h-[2.5rem]`. 내용에 따라 약 120px까지 자라고 이후 내부 스크롤.
  `resize:none`.
- **높이 재계산**: `ChatPage`는 상시 마운트되고 비활성 탭일 때 `display:none`이라, 마운트 시점 측정은
  `scrollHeight === 0`이 나온다. 그때는 인라인 높이를 건드리지 않고(찌부러짐 방지), `IntersectionObserver`로
  대화 탭이 **보이는 순간** 다시 잰다(ResizeObserver는 높이 조정이 스스로를 재트리거하는 루프가 있어 피함).
  빈 입력창은 `rows=1` + `min-h`로 한 줄 최소 높이 유지.
- **스크롤바(앱 전체)**: `.no-scrollbar` 유틸(`scrollbar-width:none` + `::-webkit-scrollbar{display:none}`)을
  홈·대화 목록·우리·추억·설정·AI 상담의 스크롤 컨테이너에, 그리고 `html`에 적용 — 막대만 숨기고
  휠·트랙패드·터치·키보드 스크롤과 `overflow-y:auto`는 그대로. 하단 탭은 스크롤 컨테이너 바깥이라
  내용을 끝까지 내릴 수 있다.
- 컨테이너는 계속 `<form>`이 아니고, 전송 키 핸들러 없음.
  - **일반 Enter**: textarea 기본 동작으로 줄바꿈. 제출/전송 경로 없음.
  - **한글 조합 확정 Enter**(`isComposing`): 조합만 확정, 여분 줄바꿈·제출 없음.
  - 둘 다 전송은 오직 전송 버튼 클릭.
- `onCompositionStart/End`를 추가하지만 `preventDefault`·`onSend`를 부르지 않는다(표현 도움 힌트 억제용).
- **검토 도구(DevPanel) 트리거 위치**: 입력창·전송 버튼과 겹치던 것을 상단 안내 줄(MockModeBanner,
  `pr-28`로 자리 확보) 오른쪽에 작은 알약으로 옮김. `aria-label="검토 도구 열기"`(테스트 셀렉터 유지).

### 대화 목록 스크롤 (`MessageList` + `scrollBehavior.ts`)

- **첫 진입**: 대화 화면이 실제로 보이고 레이아웃이 잡힌 뒤(`IntersectionObserver`) 최신 메시지로 한 번만 이동.
- **탭 재방문**: 아무 것도 하지 않음 → `MessageList`가 언마운트되지 않으므로 스크롤 위치가 DOM에 그대로 유지.
- **내가 전송**: 항상 최신 메시지로 이동.
- **새 메시지 수신**: 직전에 하단 근처(`NEAR_BOTTOM_PX = 80`)를 보고 있던 경우에만 따라감 —
  과거 대화를 읽는 중에는 가만히 둔다.
- **기존 메시지의 상태만 변경**(전송 중 → 저장 완료 등): 스크롤하지 않음.
- 판정 로직은 순수 함수 `shouldFollowToBottom` / `isNearBottom`로 분리해 유닛 테스트.
- `MessageBubble`에 `whitespace-pre-wrap break-words` — 전송한 메시지의 줄바꿈 유지. 추억 스냅샷
  (`quoteBody`)도 같은 이유로 `MemoryCard`·`MemoryDetail`·홈 최근 추억·`SaveMemorySheet` 미리보기에 적용.

### 3. 홈 — '오늘의 우리' 한 화면

세 영역에 크기·여백 위계를 준다(따뜻한 색 유지, 관계 온도·점수 없음):

- **대표 영역**(`rounded-3xl`, 넉넉한 여백): 두 사람 아바타·닉네임 · `함께한 지 N일` · 오늘의 한 줄.
- **작은 바로가기**(`rounded-2xl`, 작게): 이번 주 대표 발견 **제목을 먼저** → `우리` 탭.
  `aria-label="이번 주 우리 리포트 보기"`.
- **이미지 영역**: 최근 추억 2건. 이미지가 있으면 `ExampleImage`(가로), 없으면 글 중심.

**연결 화면과 모순되지 않게 상태를 구분한다**(대화 코칭·`WeekPage.ReportBody`와 같은 우선순위):

| 상태               | 오늘의 한 줄                                                                       | 우리 리포트 미리보기                          |
| ------------------ | ---------------------------------------------------------------------------------- | --------------------------------------------- |
| 분석 철회          | "AI 분석이 중단되어 오늘 요약을 만들지 않아요" + 설정 링크                         | "AI 분석이 중단되어 리포트가 생성되지 않아요" |
| 대화 부족(`empty`) | "오늘은 아직 나눈 대화가 없어요" + 대화 링크                                       | "리포트를 만들 만큼 대화가 많지 않았어요"     |
| AI 준비 중         | "오늘 대화를 살펴보고 있어요…"                                                     | "이번 주 리포트를 준비하고 있어요"            |
| AI 장애            | "지금은 오늘 요약을 불러올 수 없어요"                                              | "지금은 리포트를 불러올 수 없어요"            |
| 발견 없음          | (요약 예시)                                                                        | "이번 주는 특별히 눈에 띈 흐름은 없었어요"    |
| 정상               | `getTodaySummary()` + `예시` 배지 + "AI 요약 예시예요 · 실제 분석 결과가 아니에요" | `이번 주 발견 · {headlineObservation.title}`  |

홈은 `usePatterns()`·`useScenario()`·`useSettings()`·`useMemories()`만 읽고 대표 발견·추억
데이터를 따로 관리하지 않는다.

### 4. 작성 중 표현 도움 — 화면 검토용 예시

- **개인 설정**(`UserSettings.draftHelpEnabled`, `userKey`), **기본 꺼짐**. 설정 토글을
  `disabled`/"준비 중" 제거하고 실제로 배선.
- 지정된 예시 문구(`SEED_DRAFT_HELP_EXAMPLES`, 공백 포함 **구** 단위 매칭 — '왜' 같은 단어 하나로는
  경고하지 않음)에 대해서만, 입력창 위 얇은 한 줄로 이유 + **적용 전에도 실제 대체 문장**을
  (`이렇게: "…"`) 함께 보여준다(모든 예시에 대해). **화면 검토용 예시임을 라벨로 표시.**
- `이렇게 바꾸기`를 눌러야만 적용. 클릭 시점의 현재 초안을 다시 확인해, **매칭된 첫 구간만** 교체하고
  나머지 입력은 보존한다. 같은 표현이 여러 번이면 첫 곳만 바꾼다. 이음매 부호 중복 정리는
  **같은 줄에서만**(`[ \t]*[?!.]+`) — 줄바꿈을 넘어 다음 줄이나 그 줄의 문장부호("…")를 지우지 않는다.
  자동 수정·자동 전송 없음, 확인 창 없음.
- 초안 파생값이라 오래된 제안이 상태로 남지 않는다. 한글 조합 중에는 힌트를 갱신·표시하지 않는다.

**개인 설정 ↔ 양측 분석 동의 관계**: `draftHelpEnabled`는 `coupleAnalysisActive`와 **완전히 독립**.
상대 메시지를 읽지 않고 `coachingService`/`patternService`를 거치지 않으며, 본인이 친 텍스트를
고정 예시 목록과 대조할 뿐이다. 분석 철회 상태에서도 켜면 동작하고, 켜도 분석 동의 상태는 안 바뀐다.

**계정 전환 시 초기화 범위**: `draftHelpEnabled` 값은 `userKey`에 저장돼 계정별로 유지(민준이 켜도
서연은 기본 꺼짐, 전환 시 `SettingsContext`가 새 계정 값을 다시 읽음). 화면에 떠 있던 힌트는
`draft` 파생값이라 `ChatPage`가 계정 전환 시 초안을 비울 때 함께 사라진다.

**범위 밖**: 대화 중간 인라인 코칭, 지정 예시 밖 임의 문장 분석, 상대 대화 기반 표현 도움(후속 0005 계열).

### 5. 추억 화면 — 길이·예시 보완

- **'AI가 발견한 순간'**: 대표 하나(`SEED_MEMORY_SUGGESTIONS[0]` = 여행)를 먼저 보여 주고
  나머지는 `발견 더 보기 · N`으로 펼친다 — '우리 앨범'까지 과도한 스크롤을 막는다.
  펼침 상태는 추억 탭을 다시 열면 초기화(탭 재마운트), 계정 전환에는 별도 접힘 가드를 두지 않음
  (계정별로 격리할 편집 초안이 없음).
- **예시 다양화(제안 + 앨범 시드 모두)**: 피로·갈등뿐 아니라 여행·감사·농담·즐거운 순간 포함.
  기존 `SEED_MESSAGES`(코칭 근거 pat-1이 의존)는 건드리지 않고, 새 예시는 `archived-msg-*`
  방식으로 추가. 새 앨범 추억의 `savedAt`은 9~19일 전 범위 — 최신 2건(대화 1 + 사진 1)과
  최오래 앵커(`mem-seed-sea`)를 고정해 홈 '최근 추억'이 사진1+대화1을 유지하고 정렬 검증도 유지.
- **기존 저장 데이터 자동 초기화 없이 새 예시 확인**:
  - AI 발견 제안은 `listSuggestions`가 매번 시드 상수를 읽어 초기화 없이 즉시 반영.
  - 앨범 시드 추억은 DevPanel `추억 · 화면 검토`의 `예시 추억 채우기` 버튼
    (`memoriesService.seedMissingMemories`) — 저장소에 **id도 sourceMessageId도 없는** 시드만
    덧붙인다. 예시를 지우고 같은 메시지를 사용자가 다시 저장했다면(메시지당 추억 1개 규칙) 시드를
    또 넣지 않아 중복이 안 생기고 사용자 메모가 유지된다. 직접 저장·수정한 추억은 건드리지 않는다.
    일부러 지운(재저장하지 않은) 예시는 다시 나올 수 있음을 문구로 안내(명시적 리뷰 동작).
- 간직하기 / 개인별 숨김 / 중복 저장 방지 / 저장자만 수정·삭제 / '그때의 우리' 리마인드 /
  계정 전환 초안 폐기 — 유지.

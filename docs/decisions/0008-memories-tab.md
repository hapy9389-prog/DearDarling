# 0008 — 추억 탭: 대화→추억 저장, AI가 발견한 순간, 그때의 우리

날짜: 2026-09-09

## 배경

0003 구현 상태표에서 `추억 화면 · 대화→추억 저장 흐름`은 "구현 예정 — 자리표시자만 있음(Phase C)"으로
남아 있었다. `MemoriesPage`는 `StateCard` 하나, 홈의 "최근 추억"은 하드코딩된 빈 문구였다.

추억 탭을 **의미 있는 이미지와 대화 기록을 함께 돌아보는 앨범**으로 구현한다. 여전히 실제
AI·DB·사진 업로드를 연결하지 않는 가상 데이터(커플 단위 `localStorage`) 화면 검토 단계다.
AI 발견·리마인드·예시 이미지는 **가상 예시임을 항상 표시**해 사용자의 실제 추억으로 오해하지 않게 한다.

## 결정

### 1. 추억 탭은 세 영역

- **① 그때의 우리** — 앨범에 저장된 추억에서 파생한 리마인드. 후보가 있을 때만 표시.
- **② AI가 발견한 순간** — 시드 예시 제안. `우리` 탭 `ReportBody`와 같은 우선순위로 양측 분석 동의·AI
  상태에 따라 게이트한다. `예시` 배지 + "실제 분석 결과가 아니에요" 안내.
- **③ 우리 앨범** — 저장된 추억. **게이트 없음** — 직접 저장한 추억은 분석 동의와 무관하게 유지·조회·
  수정·삭제할 수 있다(0003 §4). 사진 중심 카드와 대화 중심 카드가 저장일 구분선 아래로 섞여 흐른다.

### 2. 대화 화면에서 저장

- `MessageBubble`에서 `status === 'saved'`인 말풍선만 탭 대상(내/상대 메시지 모두). `sending`·`failed`는
  진입점 없음 — 저장이 확정되지 않은 메시지는 저장할 수 없다(0002와 같은 규칙).
- **말풍선 탭(마우스·터치·Enter·Space) → 액션 메뉴 → '추억으로 저장' → 미리보기**. 텍스트를 드래그
  선택 중이거나 스크롤로 판단되는 포인터 이동(>8px)이면 메뉴를 열지 않는다.
- 미리보기: 메시지 내용 인용 · 보낸 사람 · 대화 날짜 + 선택 메모 + "저장하면 상대에게도 보여요." 안내.
  저장 전 취소·배경 탭·Esc면 저장되지 않는다. 시트를 닫으면 원래 말풍선으로 포커스가 돌아온다.
- 이미 저장된 메시지는 메타행에 `추억에 저장됨`을 표시하고, 탭하면 "추억에서 보기"만 안내한다.
- **메시지당 추억 1개**. 직접 저장·AI '간직하기' 모두 `sourceMessageId`로 중복을 막는다.

### 3. AI가 발견한 순간 — 공유 범위

- 발견 목록은 **두 사람 각자에게 동일**(커플 분석 산물). 조작 전에 범위를 안내한다:
  "간직하면 두 사람의 앨범에 저장돼요. 숨기기는 내 목록에서만 적용돼요."
- **'숨기기' = 개인 적용**(`userKey`) — 상대의 발견 목록에는 그대로 남는다. (양측 적용으로 바꿀지는 후속.)
- **'간직하기' = 커플 공유 저장**(`saveMemory`, `fromSuggestion: true`). 그 제안은 목록에서 사라진다.
- 간직한 추억을 나중에 삭제하면 같은 제안이 다시 보일 수 있다 — 정상이며, 다시 '간직하기'를
  누르기 전에는 저장되지 않는다.

### 4. 그때의 우리

- **현재 앨범에 저장된 `Memory`만** 후보로 쓴다. 삭제된 추억을 시드로 되살리지 않고, 후보가 없으면
  아무 것도 그리지 않는다.
- 마일스톤(일: 100·200·300·500, 연: 1~5년)에 **정확히** 걸리면 "100일 전 오늘" / "1년 전 오늘",
  **±3일 근사**면 "약 100일 전" / "약 1년 전". 연 단위는 365일 곱셈이 아니라 **달력 날짜(같은 월·일)**로
  센다. 날짜 구분선과 리마인드 계산은 같은 시간대(로컬 자정) 기준을 쓴다.
- '이 리마인드 닫기'는 **개인 적용**이고 "그 추억 + 그 마일스톤" 조합만 닫는다 — 100일 리마인드를
  닫아도 이후 1년 리마인드는 그대로 뜬다.

### 5. 메모 수정은 순서를 바꾸지 않는다

`updateNote`는 `note`·`noteUpdatedAt`만 갱신하고 `savedAt`은 그대로 둔다. 정렬·저장일 구분선이 움직이지 않는다.

### 6. 상태 관리 — 전역 `MemoriesProvider`

`PatternContext` + `weeklyFindingsPresent`와 같은 이유·패턴:

- 추억 탭을 연 채로 DevPanel 검토 토글을 바꾸면 즉시 반영돼야 한다(DevPanel은 오버레이).
- **대화 화면은 상시 마운트**라 추억 탭의 삭제 결과를 배지·중복 방지에 바로 반영해야 한다.
- 홈·추억 탭 어디서 저장·수정·삭제해도 서로 즉시 반영.

계정을 전환하면 개인별 파생 목록(숨긴 제안, 닫은 리마인드)만 다시 계산한다 — 커플 공유 `Memory[]`와
저장된 숨김·닫기 선택 자체는 건드리지 않는다. 메모 초안·메모 수정 editing·시트 열림은 컴포넌트
로컬 상태 + 계정 전환 렌더 가드로 격리한다(`ChatPage`가 초안을 비우는 것과 같은 규칙).

### 7. 예시 이미지

- `ExampleImage`가 `variant`로 결정되는 **일러스트풍 SVG**를 그리고 항상 `예시 이미지` 라벨을 붙인다.
  실사 사진이 아니고 자산 파이프라인을 만들지 않는다.
- 직접 저장 흐름은 이미지를 만들지 않는다 — 예시 이미지는 시드 앨범·AI 제안에서 간직한 추억에만 붙는다.

### 8. 검토 도구(DevPanel)

- 데이터 초기화·계정 전환 안내 문구에 "추억"과 "작성 중인 추억 메모"를 포함한다.
- `추억 · 화면 검토` 섹션: `AI가 발견한 순간 켬/끔`, `그때의 우리 리마인드 켬/끔`. 컨텍스트를 통해
  추억 탭에 즉시 반영되고, **기존 추억·숨김·닫기 데이터는 바꾸지 않는다**.
- '그때의 우리 켬'은 앵커 예시 사진 추억의 대화 날짜 + 100일을 **리마인드 계산 기준 시각으로만**
  덮어쓴다 — 실제 저장 날짜·목록 정렬에는 영향이 없다. 그 추억을 삭제하면 켜도 뜨지 않는다.

## 데이터

- `coupleKey(coupleId, 'memories')` → `Memory[]` (커플 공유)
- `userKey(userId, 'hiddenMemorySuggestions')` → `string[]` (개인)
- `userKey(userId, 'dismissedRememberWhen')` → `string[]` (개인, `memoryId#milestone`)
- `devKey('memorySuggestionsPresent')`, `devKey('rememberWhenEnabled')` (리뷰어)
- AI 발견 제안 원본은 시드 상수(`SEED_MEMORY_SUGGESTIONS`), 저장하지 않는다.

`Memory`는 저장 시점 스냅샷(`quoteBody`/`quoteSenderId`/`conversationAt`)을 담아 원본 메시지가 없어도
그대로 보인다. `sourceMessageId`는 중복 방지와 대화 화면 배지에만 쓴다.

## 이후 단계 (범위 밖 — 0005에 함께 기록)

- 실제 사진·영상 업로드(0005 `MessageAttachment` 연동), 사진 내용 AI 분석, AI 이미지 생성.
- 실제 대화 분석으로 '발견한 순간' 생성(0004 규칙 준수), 주기적 생성.
- '그때의 우리' 실제 날짜 매칭·알림·기념일 인식·앨범 컬렉션.
- 메시지 여러 개(대화 구간) 추억 저장, AI 제안 '숨기기'의 양측 적용 여부 재검토.
- 원본 메시지 삭제 기능 도입 시 추억–원본 관계 정책, 분석 철회 후 데이터 수명(0004에서 미정).
